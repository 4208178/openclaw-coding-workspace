# 技能：代码审查助手 (Code Review Assistant)

**角色**: CTO (蜜蜂)  
**目的**: 自动审查代码，确保符合“五要素”（正确性、可读性、可测试性、性能、安全性）。  
**触发**: 手动调用 (`/review`) 或 CI/CD 自动触发。

## 审查五要素
1. **正确性**
   - 逻辑是否正确？
   - 边界条件是否处理？
   - 异常情况是否考虑？
2. **可读性**
   - 命名是否清晰？
   - 注释是否充分？
   - 结构是否合理？
3. **可测试性**
   - 是否易于测试？
   - 测试覆盖率是否足够？
   - 是否有单元测试？
4. **性能**
   - 是否存在性能瓶颈？
   - 是否需要优化？
   - 是否考虑了扩展性？
5. **安全性**
   - 是否存在安全漏洞？
   - 输入是否验证？
   - 是否有注入风险？

## 执行流程
1. **扫描变更**：`git diff` 获取当前 PR 或工作区变更。
2. **静态分析**：运行 `eslint` + `prettier` 检查代码风格。
3. **单元测试**：运行 `jest --coverage` 检查测试覆盖率。
4. **人工审查**：CTO 基于上述结果，生成审查报告。
5. **反馈修正**：提供具体改进建议，开发者修改后重新审查。

## 输出格式
```markdown
## 🛡️ 代码审查报告

**文件**: `src/example.ts`  
**变更**: +10 lines, -2 lines

### ✅ 通过
- 逻辑正确，边界条件已处理。
- 命名清晰，注释充分。

### ⚠️ 警告
- **性能**: 循环内存在重复计算，建议提取到变量。
- **安全**: 用户输入未验证，建议添加 `zod` 校验。

### ❌ 失败
- **测试**: 覆盖率不足（当前 65%，目标 80%），请补充单元测试。

**建议**: 修复警告后重新提交审查。
```

## 依赖工具
- `eslint`
- `prettier`
- `jest`
- `typescript`

## 配置
- `ESLINT_CONFIG`: `.eslintrc.js`
- `PRETTIER_CONFIG`: `.prettierrc`
- `JEST_CONFIG`: `jest.config.js`
